# Contributing

Thanks for helping improve repo-visuals.

## Before opening a pull request

1. Keep the Skill focused on repository launch visuals rather than general-purpose image generation.
2. Preserve deterministic text rendering: generated backgrounds must not contain titles, logos, badges, or claims.
3. Add or update a behavioral test when changing a script.
4. Run the checks documented in the project README.
5. Do not commit API keys, private repository content, or generated assets without permission.

Small, focused pull requests are easiest to review. For a new asset type or a material workflow change, open an issue first and include a real use case.
